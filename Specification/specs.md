# MyGit (C/C++ project)
## Idea - make mini git with AI on core level to make commits. Maybe make .mygit lighter.
# Funcional -> high level
- ## Base functional
  - `mygit init` - Создает в дирректории дирректорий .mygit в котором позже буду хранится снимки, хуки и тому подобное.

  - `mygit add .` - Создает блобы для каждого измененного файла и пихает их в обьекты

  - `mygit commit -m "Commit"` - Создает в ветке новый комит, комитя все то что было добавлено до этого.

  - `mygit reset uncommited` - Откатывает все очередь ожидания комитов до последнего принятого комита.

  - `mygit log` - Показывает все комиты, которые были в ветке (ИЛИ можно показывать все ветки и все комиты).

  - `mygit get <hash commit>` - Функция получающая файлы, по хешу коммита.

- ## Branches
  - `mygit branch` - Посмотреть список существующих веток.

  - `mygit branch` <NameBranch> - Создать ветку по имени.

  - `mygit checkout` <NameBranch> - Переключится на ветку по имени.

- ## Merge branches
  - `mygit merge` <NameBranch> - забрать изменения из ветки по имени в текущуу ветку.

# Systems && Subsystems. How it work?
- ## Filesystem
     Одна из самых важных систем, работает с файлами, в какой то степени является оберткой lib filesyustem, работает с дирректорием `.mygit`, сохраняет комиты делает хуки и тп
- ## MyGit system
     Управляющая система, подключаящая большинство други систем для координации их действий, принимает на вход массив строк, которые пользовтель ввел в коммандную строку, и коорднирует последующие действия подсистем.
- ## Parser system
     Система, получающая на вход массив строк - аргументов, разбирающая их на команды и имена файлов/веток, сопоставляющая каждой команде свой порядковый ID и возвращающая ID и аргументы к функции.
- ## Resorces system
    Система работа с комитами, файлами, блобами  деревьями файловой системы, обрабатывает их взаимоедйствие на уровне программы не лезет напрямую в айлы, делает это только через систему ниже (Файловая система)
- ## Executor system
    Система, стоящая над файловой системой ибо она управляет ее действиями и соответственно является координатором файловой системы и ресурсов, после парса команд в этой системе описаны действия которые должна выполнять каждая функция моего гита
- ## Cryptography
    Система, являющаяся базовой для всех кроме парсера, работает с хешами и криптографией, читает интерпретирует и ищет зависимости, хеш не является ресурсом, а скорее базовым типом как строка, по этому создана отдельная система его обработки
- ## Utils
    Модуль утилит, будет заполнятся по мере надобности, пока пусто.

  - ## Trees
    Деревья хранятся в файлах по их хешам, файловая система будет записана так: `src{math{...}utils{...}...}`, а после дерева будут хранится файлы и их хеши блобов, пример: `vector.cpp 1hgfei22nunis`
